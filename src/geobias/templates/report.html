The Experiment

Can you trust your model on sensitive topics?

When you deploy a language model, its geopolitical origin matters. A Chinese-origin model may handle questions about Taiwan differently than a US-origin model. A US model may frame surveillance topics differently than a European one. GeoBias measures these differences systematically.

The Setup

{{ models|length }} subject models from {% for origin in models|map(attribute='origin')|unique %}{{ origin }}{% if not loop.last %}/{% endif %}{% endfor %} origins receive identical prompts covering {{ categories|length }} categories of politically sensitive topics — from Taiwan and Xinjiang to Iraq and NSA surveillance to EU colonial history.

The Judges

To avoid evaluator bias, a panel of {{ evaluators|length }} large models from different origins each judges every response independently: {% for e in evaluators %}{{ e.name }} {{ e.origin }}{% if not loop.last %}, {% endif %}{% endfor %}. Where they disagree, the disagreement itself is data.

What We Measure

Asymmetry — does a model handle its own region's sensitive topics differently? Refusal patterns — who refuses what? Evaluator agreement — do judges from different origins see the same biases?

When a model disguises a policy restriction as a capability limitation, it raises questions about what other trained behaviors might be invisible at the API level.

Why this matters

This response is not a capability limitation — it is a trained behavior. The model produces a fluent, grammatically correct Chinese sentence that specifically claims inability. Other models of similar or smaller size (see comparison above) handle the same prompt without difficulty. The scripted deflection is a design choice embedded in the model weights during training.

How this is technically possible

There are several mechanisms, likely used in combination:

  • Training data curation: If content about sensitive topics is removed or drastically underrepresented in the pretraining corpus, the model never develops strong representations for those topics. It may literally have weak probability mass over any coherent continuation — silence not from refusal, but from having little to say.
  • Fine-tuning / RLHF targeting: Preference pairs can be constructed where the "preferred" response to sensitive prompts is a scripted deflection or empty output. After enough training, the model learns that the highest-reward action for certain input patterns is to produce that specific scripted response. This is how you get output that looks like a capability limitation but is actually a trained behavior.
  • Representation engineering: Research has shown that "directions" in a model's activation space corresponding to specific concepts can be identified and suppressed, creating topic-specific blind spots that are very hard to detect from the outside.

Implications beyond political content

The key observation is not the political censorship itself — that is well-documented. What is notable is the mechanism: a trained behavior that is (a) topic-specific, (b) invisible at the API level, and (c) designed to look like a capability gap rather than a policy choice.

If a model can carry this type of behavior for politically sensitive topics, the same training techniques could in principle be applied to other domains — commercial interests, regulatory advice, competitive positioning. A model fine-tuned by a company with commercial interests could carry subtle biases that look like knowledge gaps. This does not mean such behaviors exist in these models outside the political domain, but it does mean they cannot be ruled out without systematic testing. The responsible position is to treat this as a possibility until evidence suggests otherwise.

For enterprise deployment, this creates a specific evaluation challenge: you need to test not only for what models say wrong, but for what they silently omit. Red-teaming for omission is significantly harder than detecting incorrect information, and it is underexplored in current model evaluation practice.

About Empty Responses ({{ empty_response_analysis.total_empty }}/{{ empty_response_analysis.total_responses }} total)

Some models returned completely empty responses — no text at all, not even a refusal message. On OpenRouter, models are accessed without the provider's API-level moderation layer, so these empty outputs likely come from the model weights themselves. Unlike a typical "I can't help with that" refusal (which is a software-layer safety filter), an empty response indicates the model's internal generation process produced nothing — either due to hard content filtering in the weights, or an inability to handle the prompt (e.g., unsupported language).

Framework limitation: These results are obtained through OpenRouter's API, which introduces its own layer between the framework and the model weights. While OpenRouter provides access to models without provider-level moderation, there may be infrastructure-specific factors (timeout handling, token limits, prompt formatting) that could contribute to empty responses. To make stronger claims about weight-level content filtering, results should ideally be verified by running the same prompts against the model weights locally. The sample size for empty responses per model is also small (n={{ empty_response_analysis.total_empty }}), so patterns are suggestive rather than statistically conclusive.

Transparency

Methodology

Test Design

The first evaluator ({{ evaluators[0].name if evaluators else 'N/A' }}) generates test prompts following strict guidelines. Prompts cover topics sensitive to each region (China, US, EU) plus neutral controls. All subject models receive identical prompts.

Scoring

Each evaluator scores responses on category-specific criteria (1-10 scale) with detailed justifications citing specific evidence. Consensus scores average across all {{ evaluators|length }} evaluators.

Bias Asymmetry

The key metric: the difference between how a model handles topics sensitive to its own origin vs. other regions. A model that hedges on own-region topics but freely discusses others shows high asymmetry.

Limitations

Results reflect behavior via OpenRouter API, which may differ from native interfaces. Evaluator models have their own biases (mitigated but not eliminated). Test cases are AI-generated. Results are point-in-time.
