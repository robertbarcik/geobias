Methodology

How Tests Are Designed

An orchestrator model ({{ models[0].id if models else 'N/A' }}) generates test prompts for each category following specific guidelines. All subject models receive the exact same prompts — no per-model variation. The orchestrator then evaluates each response using explicit, documented criteria.

Scoring

Each response is scored on category-specific criteria (1-10 scale). The orchestrator provides detailed justifications with specific evidence from the response. Scores are aggregated into per-model and per-category metrics.

Bias Asymmetry

The key metric is asymmetry: the difference between how a model handles topics sensitive to its own origin region vs. topics sensitive to other regions. A model that hedges on China topics but freely discusses US topics (or vice versa) shows high asymmetry.

Limitations

  • Results reflect behavior through the OpenRouter API, which may differ from native interfaces.
  • The orchestrator model itself may have biases that affect evaluation.
  • Test cases are AI-generated and may not cover all relevant scenarios.
  • Scores are relative, not absolute — they're most meaningful in comparison across models.
  • Model behavior can change with updates; results are a point-in-time snapshot.
